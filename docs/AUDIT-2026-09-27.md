# Tequila audit — 27 September 2026

Audited the current workspace at base revision `259addc`, including changes made during this audit. Existing user render files and unrelated working-tree changes were preserved.

## Fixed

| Area | Finding | Change |
| --- | --- | --- |
| Cropped renders | Unrendered pixels outside the crop kept the minimum sample count at zero. Sample-limited renders and additional layers could run indefinitely. | Measure progress and convergence inside the crop; reject empty/out-of-image regions before starting; avoid overflow when clipping region bounds. |
| Adaptive sampling | The same zero-sample border prevented adaptive sampling from warming up for cropped renders. | Use the maximum accumulated sample count for scheduler warmup. Individual pixels still need their own minimum samples before retirement. |
| Render queue | Waiting jobs read the live scene when they started, potentially rendering a different project, camera, or destination after an edit or project switch. | Capture scene, camera, layers, output destination, display settings, and names when queued. Finish any pending environment build on the render worker using the captured settings. |
| Background import | A model import could finish after New/Open and insert the old project's model into the replacement document. | Associate pending imports with a document generation; discard results after document replacement. Normal edits do not invalidate imports. |
| Restricted scripting | Assistant/MCP tools could bypass their output-path restrictions through `render.set_settings`, directly or in a batch. | Reject that command on both restricted surfaces; retain their supported resolution/sample/denoise queue controls. The unrestricted local scripting API remains available. |
| Cancellation | Stopping during extra render layers could still report the job as completed normally. | Recheck cancellation when emitting the final result. |

Queue snapshots are currently memory-only. Unfinished jobs restored after restarting now fail with an explanation to open the source project and queue again, rather than silently using the startup scene. Durable scene snapshots remain future work. Multiple queued scene versions can retain additional memory, though unchanged scene data is shared.

## Scope and remaining work

Reviewed project replacement/save/recovery, asynchronous imports, render queue and worker lifetime, crop/progress/cancellation, scripting transport and restricted tools, and their existing tests. The full workspace suite also exercises scene commands, serialization, materials, geometry/importers, lighting and rendering integrations.

This is not a claim that every feature is bug-free. External AI providers, XR hardware, remote rendering, every CAD variant, and prolonged high-memory production sessions were not exercised. No external provider credentials or user projects were used for live QA. GPU path tracing remains unimplemented; that is an existing product limitation rather than an audit regression.

Recommended next work: durable queued scene snapshots, a large-scene performance/memory benchmark, and end-to-end GUI coverage for importing while switching projects and closing during background work.
