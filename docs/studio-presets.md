# Studio presets

A studio preset is a whole studio for a kind of product, kept as one thing
and put on any product in one step:

- the lights, each placed relative to the product;
- the cameras and the **views** (Studios) that pick between them, switch
  lights on and off, and turn the product;
- the environment and the floor: reflections, their fade, the ground
  bounce;
- the look (image style) and the render and lighting settings, Cycles'
  finer controls included;
- optionally, the materials the studio is meant for and **rules** that put
  them on parts by their names.

A preset is framed for a product of one size, its **reference radius**. On
a product twice that size, the cameras stand twice as far off and see the
same picture. Presets of one **family** come in **sizes** (Small, Medium,
Large), and the Library marks the size nearest the product in the scene.

## In the application

Tequila comes with one, **Soft Studio**: three softboxes on a seamless floor
with a soft shadow and a short reflection, with Hero, Front, Side, Back and
Top views, all rendered as transparent 16-bit PNGs. It's generated by
`crates/tequila-format/examples/builtin_studios.rs` and uses no pictures.

**Library → Studios.** The family's sizes sit side by side, and *Suggested*
marks the one framed nearest the product. Click a preset to choose:

| Option | What it does |
|---|---|
| The product's front faces | The side of the product that should face the Main camera: +Z, −Z, +X or −X. CAD files arrive any way round. |
| Scaled to the product | What follows the product's size: the cameras (the default), the cameras and the lights, or nothing. |
| Keep my lights | Leave the scene's lights as they are, and bring only the rest. |
| Keep my cameras too | Leave the cameras alone as well. |
| Leave the product where it is | Don't centre the product or stand it on the floor. |
| Dress it with the studio's materials | Put the preset's materials on parts by their names. Off, they're only added to the project. |

**Apply** is one undo step: one Ctrl+Z takes back the studio, the framing
and the dressing together.

The preset's lights go into a group called *Studio lights*. It replaces the
scene's top-level lights and any group an earlier preset brought, unless you
keep your lights. The first view is applied; the **Studio**
tab switches between views, and **Render all N views** queues one render
per view.

**Save current studio…** keeps everything in the scene but the product as a
preset of your own, framed for the product you have now, with the viewport
as its picture. Saving it and applying it to the same product gives the same
scene back. **Install…** takes a `.tqstudio` package, or a preset's
`.studio.json`. **Export…** writes one to share, and **Delete…** removes one
of your own (the built-in ones stay).

## Views

A view is a [Studio](file-format.md#31-top-level) that a preset brings. On top of
what a Studio always held (camera, environment, look), a view may say:

| Field | Meaning |
|---|---|
| `lights` | `[{"name": "Rim", "enabled": false}, {"layer": 2, "enabled": true}]`: lights switched by name, or by light layer. |
| `product_yaw` | How far the product turns about its vertical axis for this view, in radians, right-handed about +Y. The next view turns it back. |
| `filename_suffix` | What `{view}` (and `{studio}`) is in a render's file name. Default: the view's name. |

The output template's `{product}` is the project's name, `{view}` the view,
and `{date}` the day: a preset's `{product}_{view}_{date}` names five
renders `Speaker_Main_2026-10-29.png`, `Speaker_Top_2026-10-29.png`, and so
on.

## From a script or an AI app

```python
import tequila
fs = tequila.connect()
best = fs.studios.suggested()                 # the size nearest the product
fs.studios.apply(best['id'], front='-z', dress=True)
for job in fs.studios.render_all():
    fs.wait_for_job(job)
```

| Request | Fields |
|---|---|
| `{"op": "studio_preset", "action": "list"}` | Every preset installed. Each lists its `views`, `reference_radius_m`, and `suggested`. |
| `"action": "apply"` | `preset`: the installed preset's id. Optional: `front` (`+z`, `-z`, `+x`, `-x`), `scale` (`cameras`, `cameras_and_lights`, `none`), `keep_lights`, `keep_cameras`, `keep_placement`, `dress`. |
| `"action": "save"` | `name`, and optionally `family`, `size`, `description`, `materials`. |
| `"action": "install"` / `"export"` | `path` (and `preset` to export). |
| `"action": "delete"` | `preset`. Only your own presets. |
| `"action": "render_all"` | Queues every view. Returns `jobs`. |

A headless session (`tequila.open()`) answers the same requests. There,
`render_all` renders every view before it answers, and returns the files'
`paths`. Give it a `path` with `{view}` in it, or it uses the project's own
output folder and name.

From the command line, one product through a studio, every view:

```bash
tequila -i product.step --studio-preset product-studio-small --front -z --dress --all-studios -o "renders/{product}_{view}_{date}.png"
```

`--studio-preset` takes an installed preset's id, or a preset's folder or
`.studio.json`. The render then uses the preset's settings: engine,
resolution, samples, alpha, and 16 bits when the preset asks for them.
`--all-studios` also works on a saved project that has Studios.

As a command, `{"command": "studio_preset.apply", "preset": "<id>", "options": {...}}`
applies an installed preset by its id. The journal records the whole preset
in the command, so a replay doesn't depend on what's installed. The MCP
bridges offer `tequila_studio_presets`, `tequila_studio_preset_apply`,
`tequila_studio_preset_save` and `tequila_studio_render_all`.

## The format

A preset is a folder, and a `.tqstudio` file is that folder zipped:

```
product-studio-medium/
├── product-studio-medium.studio.json
├── thumbnail.png
├── textures/          the HDRI, backplate and image pins it uses
└── materials/         its materials, as material library presets
```

Every path in the file is relative to the folder, and none may leave it.
`..`, an absolute path or a drive letter is refused, and so is a zip member
that would land outside the folder. The schema is
[`schemas/studio-preset.schema.json`](schemas/studio-preset.schema.json).

| Key | Type | Meaning |
|---|---|---|
| `format` | `"tequila.studio-preset"` | Required. |
| `version` | integer | Required. `1`. A newer version is refused with a reason. |
| `id` | string | Required. Names the folder: letters, digits and dashes. |
| `name` | string | Required. What the Library shows. |
| `family`, `size` | string | Presets of one family are one studio in several sizes. |
| `description`, `tags`, `preset_version`, `notes` | | Free text, for people. |
| `thumbnail` | path | A picture for the Library; 4:3 reads best. |
| `environment` | object | As in a project's `scene.json`: environment and `ground`. |
| `lighting` | object | As in a project, `custom.cycles` included. |
| `render` | object | As in a project. The project keeps its own output folder, render layers and region. |
| `image_style` | object | As in a project. |
| `lights` | array | `{"name", "light", "transform"}`. `light` is a light as a project writes it. `transform` is 16 numbers, row by row, in the studio's space: the product stands centred on the origin. |
| `cameras` | array | Cameras as a project writes them, framed for the reference radius. |
| `studios` | array | The views (see above). |
| `framing` | object | `reference_radius_m` (required, above 0): the radius of the product's bounding sphere, which is half its bounding box's diagonal. `base_offset_m`: the height of the product's base above the floor. `scale`: `cameras`, `cameras_and_lights` or `none`. |
| `materials` | array | Paths of material presets in the folder. Installing adds them to the material library, under their category. |
| `material_rules` | array | `{"pattern", "material"}`: parts whose names match the `*`/`?` pattern wear the material named. They become a Material Template called *<name> materials*, which you can run again or change. |

Keys this version doesn't know are kept, and written back when the preset
is exported.

## Back compatibility

Every field the presets brought is optional, and its default is what
Tequila did before:

- a ground with no fade distance fades by the product's height;
- reflections are cut out by coverage;
- the floor doesn't bounce light;
- materials have sharp edges and media don't glow;
- a Studio switches no lights and turns nothing;
- Cycles' bounce limits, pixel filter, clamping and noise threshold are
  set as before.

A project from before opens and renders as it did.
